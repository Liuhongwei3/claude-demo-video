# 各业务模块的叙事建议

所有模块使用同一条叙事线：**痛点问句 → 一句话价值 → 3–4 个功能（每个都有真实画面作证）→ 闭环关键词 + 两行收尾**。下表只是起点：功能顺序以 brief 为准，能讲什么以录屏里实际拍到的为准。录屏里没有的环节写进 `gaps`，不要硬讲。

模块目录名使用小写英文加连字符，`module` 写中文名。

## 通用骨架

| 段落 | 旁白句数 | 镜头数 | 标题样式 |
|---|---|---|---|
| hook | 2 | 1（列表全景 → 推近到要点的记录） | 「让 X，真正 Y 起来」 |
| 功能 ×3–4 | 2–3 | 2–4 | kicker「0N  功能 · 角色」，主标题 8–12 字 |
| closing | 1 | 1（最能代表成果的画面，定格） | 「一条链路，串起 X 全流程」 |

总时长 40–55 s，共 10–14 句旁白、12–18 个镜头。

## 生产工单 `production-order`（已有：v2 手写，v3 spec）

- 钩子：「生产工单流转慢、进度看不清？」
- 功能：工单详情与工序链路 → 工序动态调整（插入工序）→ 个人工作台与报工 → 负责人任务管理与批量派发
- 闭环：工单 → 工序 → 任务 → 派发 → 报工 → 演进
- 隐私：执行人、客户名、参与人、执行人下拉框
- 常见缺口：报工弹窗、派发提交后的结果

## 库存管理 `inventory`

- 钩子：「库存数字对不上、呆滞料看不见？」
- 可找的功能画面：库存台账（按仓库 / 库位筛选）→ 入库 / 出库单据与审核 → 调拨或移库 → 盘点（盘盈盘亏）→ 库存预警（安全库存、呆滞）→ 出入库流水追溯
- 闭环：入库 → 在库 → 调拨 → 盘点 → 出库 → 预警
- 隐私：供应商 / 客户名、经办人、单价与金额（用户允许时才保留）
- 常见缺口：审核通过后的库存数量变化（需要同一物料在操作前后两个画面）

## 质量追溯 `quality-trace`

- 钩子：「出了质量问题，查不到是哪一批、哪道工序？」
- 可找的功能画面：检验任务（首检 / 巡检 / 终检）→ 检验记录与判定 → 不合格品处理（隔离、返工、评审）→ 批次 / 序列号正反向追溯（原料 → 工序 → 成品 → 客户）→ 质量报表
- 闭环：来料 → 过程 → 成品 → 追溯 → 处置 → 改进
- 隐私：检验员、客户名、批次中的客户订单号
- 常见缺口：追溯链跨越多个页面时，需要连续录完一次完整的正向或反向查询

## 采购管理 `purchasing`

- 钩子：「采购进度靠催、到货对账靠人工？」
- 可找的功能画面：采购需求 / 请购 → 询价比价与供应商选择 → 采购订单与审批流 → 到货与收货质检 → 对账与付款进度 → 供应商绩效
- 闭环：需求 → 询价 → 下单 → 到货 → 对账 → 评估
- 隐私：供应商名称、联系人和电话、单价与合同金额
- 常见缺口：审批流的多人操作（往往需要切换账号录制，录屏中通常没有）

## 写作提示

- 每句旁白都要对应一个**动作或状态变化**（点开、插入、勾选、出现提示），不要只念菜单名。
- 角色要说清楚：「执行人员在个人工作台……」「负责人在……中」。
- 同一个功能内，第二句讲结果或价值（「即时更新」「一目了然」），但这个结果必须在画面里出现。
- 收尾的关键词链与各功能节一一对应，最后一个词点出「闭环」或「演进」。
