# 交付说明 · 生产工单全流程管理产品宣传 Demo（v2）

v2 根据 v1 的反馈修改：加长时长、改用女声并加快语速、放慢画面节奏并让过渡更自然、让画面在屏幕中占比更大。v1 原样保留在 `../v1/`，两版的对比见 `../CHANGELOG.md`。

## 交付物

| 文件 | 说明 |
|---|---|
| `production-workflow-demo.mp4` | 成片：1080×1920 竖屏，30 fps，H.264 High / yuv420p，AAC 48 kHz 立体声，时长 50.8 s，约 19 MB |
| `voiceover-script.txt` | 旁白文案（带时间码）、屏幕主标题、收尾文案 |
| `subtitles.srt` | 简体中文字幕，与旁白逐句同步（成片中已烧录同样的字幕） |
| `shot-list.md` | 镜头清单：原片起止时间、对应功能、裁切放大、字幕旁白、敏感信息处理 |
| `storyboard.jpg` | 成片关键帧组成的分镜缩略图 |
| `../../project/versions/v2/` | 本版的剪辑决策表（`edl.py`）和文案（`script.py`），用 `VIDEO_VERSION=v2 ./project/build.sh` 可一键复现 |

## 相对 v1 的改动

- **时长**：28.8 s 增加到 50.8 s。镜头从 12 个增加到 16 个，新增原片中的真实画面：工序卡悬停时的首检状态提示、工序任务详情的完整信息、插入弹窗里点击「确认新增」、侧栏切换到「任务派发管理」、任务详情弹窗（工序链路进度、执行记录）和点击「派发任务」，以及派发表单中选择工序和执行人的过程。
- **女声，语速更快**：配音从男声（Kokoro 68 号）换成女声（Kokoro 21 号）。具体做法是：先用离线语音识别对 55 个中文女声逐一评测字错率和基频，选出咬字最清楚、音高约 225 Hz（成熟、不卡通化）的一个。语速从约 4.2 字/秒提高到约 4.9 字/秒。旁白从 6 句扩写为 13 句，每个功能都有更完整的说明。
- **过渡更自然，节奏更慢**：
  - 镜头之间的交叉淡化从 0.15–0.3 s 延长到 0.45–0.6 s，并改为「形变叠化」：两个镜头共用同一张卡片，卡片外框在重叠期间从上一镜头的尺寸平滑过渡到下一镜头的尺寸，框内画面同时叠化，并带 3.5% 的轻推镜，不再出现两张不同尺寸卡片叠在一起的重影。
  - 同一页面上相邻的镜头（工序链路的总览、悬停、点击）使用同一个机位衔接，叠化时画面不跳。
  - 平均每个镜头的时长从约 2.4 s 增加到约 3.2 s，推拉镜头更慢，高亮、标题和字幕的渐入渐出也更长。
  - 结尾增加 0.7 s 淡出。
- **画面更大**：界面卡片从 960 px 宽、通常 600–1000 px 高，放大到 1040 px 宽、通常 870–1300 px 高（约占屏幕高度的 2/3）。标题区上移、字号略减，字幕下移到卡片下方，三者仍然互不重叠。
- **隐私处理更严格**：v1 保留了原片中已部分脱敏的人员姓名，v2 对出现姓名的列、执行记录和执行人下拉选项额外做了模糊。

## 质检结果（已实际检查成片）

- 编码与规格：经 ffprobe 确认为 1080×1920、30/1 fps、H.264 High、yuv420p、AAC LC 48 kHz 立体声，时长 50.800 s，可完整播放。
- 响度：整体 −16.0 LUFS，峰值 −4.7 dBFS。配音时音乐压低约 11 dB，并提前 0.12 s 开始压低，避免句首的轻声母被音乐盖住。转场音效避开旁白句首；其中一处 whoosh 的混响尾巴会让「任务派发后」被识别成「政务派发后」，已去掉。
- 配音清晰度：用离线语音识别（SenseVoice）逐句识别成片音轨，平均字错率约 4%，剩下的差异都是同音字（如「链路 / 练路」「即时 / 及时」「报工 / 报功」），读音一致。为了提高清晰度，评测过程中改写了 3 句旁白：
  - 「点开工序节点，还能……」原本会被听成「才能」，改为「点开任一工序，对应任务、前后工序一并呈现」。
  - 「任务详情与执行记录……」的句首「任务」在混音后会被听错，改为「打开任务详情，执行记录清晰可查」。
  - 「工单、工序与任务」改为「工单、工序、任务」。
- 字幕：逐帧检查，没有错字和溢出，句末逗号已去掉。超过 12 字的句子在逗号处分成两行，字幕全部位于卡片下方，不会遮挡界面。
- 构图：每 0.5 秒抽帧检查一次，并逐帧检查了全部转场。没有露出浏览器栏、任务栏、水印或弹窗外的灰色遮罩，也没有加载骨架屏或白屏。迭代中修正了三处问题：
  - 开场镜头末尾露出抽屉骨架屏：改为在点击后、抽屉出现前定格。
  - 新增成功后的抽屉刷新显得发灰：改为从原片 57.65 s 内容完整出现后开始。
  - 「执行记录」标签压在工序链路上：改为错开显示，并把标签放到表格下方。
- 业务真实性：没有伪造任何成功提示。「新增成功」是原片真实画面；报工和派发都没有展示结果（原片里没有）。

## 仍然存在的素材缺口（与 v1 相同）

1. **任务报工操作**：原片没有展开「操作 ▾」菜单或报工弹窗。成片只高亮操作列并标注「任务操作入口」，「通过操作列发起报工」由旁白讲述。**建议补录约 3 秒**。
2. **批量派发的完整结果**：原片有勾选列，派发表单里也能「添加派发」（成片中展示了派发 1 / 派发 2），但没有点击「确定」提交，也没有派发成功的结果。**建议补录约 3 秒**。
3. **画质**：B 站未登录状态下最高只能拿到 720P，v2 放大到 2 倍左右时，小字号略有发软。提供账号 Cookie 中的 `SESSDATA` 后，运行 `BILIBILI_SESSDATA=xxx python3 tools/fetch_bilibili.py BV1j8pq6oEqi source/` 获取 4K 原片，再运行 `VIDEO_VERSION=v2 ./project/build.sh`，即可按同一份剪辑决策表重新渲染出更清晰的版本，镜头坐标会自动适配。
4. **配音**：使用离线开源 TTS（Kokoro v1.1-zh，Apache-2.0），自然度不如真人。正式投放前建议按 `voiceover-script.txt` 的时间码录制真人配音，覆盖 `build/v2/vo/line_00.wav … line_12.wav`，再运行 `VIDEO_VERSION=v2 python3 project/audio.py` 并重新封装，不用重新渲染画面。
5. **品牌信息**：素材中没有 Logo 或完整产品名，结尾使用纯文字，没有虚构品牌标识。
